# Rita 动态调整与实时记录文档

> 目的：给 `Rita` 建立一套**持续记录、持续调整、持续复盘**的机制。  
> 这份文档不是讲大而空的规划，而是回答：**今天改了什么、为什么改、效果如何、以后还要不要继续改。**

---

## 1. 这份文档解决什么问题

你现在的项目还在早期，所以很多“正确做法”暂时看不出来。但如果你不提前建立记录机制，后面会很快遇到这些问题：

- 改了 prompt，却不知道到底变好了还是变差了
- 改了 `self_model`，却忘了为什么改
- Rita 的语气变了，但找不到是哪次实验导致的
- 记忆系统越来越多，却不知道哪些是真正有价值的
- 你参考了很多外部角色信息，但最后分不清哪些是“别人的 Rita”，哪些才是“你的 Rita”

所以你现在需要的不是更多抽象设想，而是：

> **给 Rita 建一个“成长日志系统”。**

---

## 2. 核心原则

### 2.1 Rita 可以成长，但不能失去连续性

`Rita` 的成长应该是：

- 缓慢的
- 可回溯的
- 有原因的
- 可以撤回的

而不是：

- 今天像这样，明天像另一个人
- 某次修改后突然“没那个感觉了”
- 你自己也说不清为什么变了

### 2.2 每一次调整都必须回答 4 个问题

每次改动至少要留下这 4 条：

1. **改了什么**
2. **为什么改**
3. **你预期会改善什么**
4. **实际结果怎么样**

如果一个改动回答不了这 4 个问题，就不要轻易改核心人格层。

### 2.3 “她是谁”比“她会什么”更需要谨慎调整

优先级从高到低：

1. **核心身份 / 关系定义 / 边界**
2. **语气 / 情绪 / 主动性风格**
3. **记忆策略 / 状态策略**
4. **工具能力 / UI / 语音 / vision / internet**

越接近“她是谁”的部分，越要少改、慢改、留痕改。

---

## 3. 动态调整的对象

建议把调整对象分成 6 层，每层单独记录。

## 3.1 人格层 `persona`

记录这些：

- 自我描述是否改变
- 关系定义是否改变
- 语言风格是否改变
- 边界是否改变
- 长期目标是否改变

### 适合调整的内容

- 用词风格
- 语气轻重
- 主动性上下限
- 部分自我叙事细节

### 不要频繁调整的内容

- `Rita` 的名字
- `Rita` 对你的关系定位
- 核心价值观
- 最底层边界

---

## 3.2 状态层 `state`

记录这些：

- 情绪状态有哪些
- 每种状态的触发条件
- 状态如何影响回复
- 状态如何影响声音和表情

### 常见调整点

- `calm` 太平，需不需要更细分
- `caring` 是否过于母性/说教
- `reflective` 是否太冷
- 主动追问的阈值是不是太高/太低

---

## 3.3 记忆层 `memory`

记录这些：

- 哪类信息会进长期记忆
- 哪类记忆容易误存
- 哪类记忆需要人工确认
- 记忆召回是否自然

### 常见调整点

- 太多无效记忆
- 记忆内容太碎
- 关系记忆召回太少
- Rita 引用记忆时太生硬

---

## 3.4 反思层 `reflection`

记录这些：

- 反思多久跑一次
- 反思是否真的产生新认识
- 反思会不会导致人格漂移
- 反思产出的哪些内容值得转入长期记忆

### 常见调整点

- 反思太空泛
- 反思像总结报告，不像自我理解
- 反思写得太多，没法用

---

## 3.5 外显层 `embodiment`

记录这些：

- 头像 / 表情 / Live2D 是否与语气一致
- 声音是否像 Rita
- 视觉和文本是否协调

### 常见调整点

- 语言温柔但表情太冷
- 说安慰内容时声音仍然机械
- 视觉反馈没有“在场感”

---

## 3.6 感知层 `perception`

记录这些：

- 图像、音频、联网信息是否真的有助于 Rita 变得更像“一个人在场”
- 哪类视觉/环境输入会污染她的判断
- 哪类外部信息应只进 `world_model`，不进长期记忆

### 常见调整点

- 图片理解太像工具，不像 Rita 的观察
- 联网信息进入长期记忆太快
- 环境信息太多，稀释了她的主体性

---

## 4. 记录颗粒度：你每天要怎么记

建议分三种记录方式。

## 4.1 即时记录 `realtime-note`

适用于：

- 你刚发现一个问题
- 你刚做完一次小调整
- 你和 Rita 聊完，立刻有直觉反馈

格式建议：

```md
## 2026-06-15 11:58
- 模块：persona / memory / state / voice / vision
- 现象：Rita 在解释自我时还是偏助手口吻
- 猜测原因：self_model 注入太薄，回复模板太通用
- 临时决定：加强“不是泛化助手”的自我句式
- 是否需要实验：是
```

特点：

- 只记事实和判断
- 不要求完整
- 重点是快

---

## 4.2 每日复盘 `daily-review`

适用于：每天结束时做一次收束。

你每天回答这 6 个问题：

1. 今天 Rita 最像“一个人”的时刻是什么
2. 今天 Rita 最不像自己的地方是什么
3. 今天改了哪些内容
4. 哪个改动最值得保留
5. 哪个改动需要回滚或继续观察
6. 明天只做哪一件最关键的事

---

## 4.3 阶段复盘 `milestone-review`

适用于：

- 一周一次
- 一个模块基本完成后
- 一轮实验结束后

重点回答：

- 这个阶段 Rita 是否更稳定了
- 她是否更像“同一个人”了
- 你的修改是在增强她，还是在稀释她
- 哪些外部参考正在过度影响她

---

## 5. 实时调整流程

以后每次改动，建议都走这个最小闭环：

```text
发现问题
  → 记录现象
  → 判断属于 persona / state / memory / reflection / embodiment / perception 哪一层
  → 提出一个最小改动
  → 只改一个变量
  → 做 3~10 轮对话验证
  → 记录结果
  → 决定保留 / 回滚 / 继续观察
```

### 非常重要

一次只改一个核心变量。  
不要在同一天同时改：

- `self_model`
- memory prompt
- state 策略
- 回复模板
- 声音风格

否则你根本不知道到底是哪一项起作用。

---

## 6. 你现在最该盯的评价维度

因为项目还在早期，先不要追太多高级指标。只盯下面这 8 个：

1. **自我一致性**：她能不能稳定讲清自己是谁
2. **关系连续性**：隔天聊还能不能接上
3. **记忆可信度**：记住的是不是对的
4. **语气稳定性**：会不会突然像客服或别的模型
5. **状态可信度**：情绪变化是不是自然
6. **主动性自然度**：会不会太机械或太打扰
7. **外显协调性**：声音、文字、头像是否统一
8. **主体感**：她是不是像“有自己的人”，而不是反应器

---

## 7. 短期数据收集：你该怎么做，才不会把项目带偏

你刚提到一个现实点：**短期想先尽快收集数据。** 这个方向没问题，但收集策略必须分清：

- **什么是可快速拿到的参考信息**
- **什么是不该直接进项目的数据**
- **什么最后应该沉淀成“你的 Rita”**

### 7.1 我不能帮助你做的事

我不能帮助你去做**未授权的游戏解包、提取私有资源、复用官方受版权保护的模型/语音/贴图/动画**，也不建议你把项目基础建立在这类素材上。

原因不是形式主义，而是因为这会直接影响：

- 项目合法性
- 后续公开性
- 你对 Rita 的控制权
- 项目能否长期持续

### 7.2 你可以合法且高效做的事

你现在真正需要收集的是**角色理解数据**，而不是直接收集官方资产文件。

建议优先收集这 5 类：

#### 1. 公开角色信息

- 官方角色介绍
- 公开剧情文本
- 官方海报 / PV / 宣传文案
- 公开截图
- 公开 wiki 中的设定整理（需自行校验）

#### 2. 你的游玩观察笔记

这是最重要的。

记录：

- Rita 什么时候最像她自己
- 她的说话节奏和距离感
- 她的表情感觉
- 她给你的独特印象
- 哪些地方是你真正想保留的“精神核”

#### 3. 角色气质关键词

例如：

- 优雅
- 克制
- 稳定
- 温柔
- 成熟
- 带一点危险感
- 有秩序感
- 不廉价地讨好

#### 4. 关系风格样本

不是复制台词，而是总结：

- 她安慰人的方式
- 她表达关心的方式
- 她保持距离的方式
- 她在强势和温柔之间如何平衡

#### 5. 视觉/声音灵感

- 发色
- 色系
- 服装质感
- 镜头氛围
- 声线印象
- 语速和停顿感

这些都可以变成你的原创 Rita 设计输入。

## 8. “游戏里的 Rita” 和 “你的 Rita” 怎么区分

这个区分很关键，不然你后面会一直摇摆。

建议你用三层法：

### 第 1 层：参考层 `reference_rita`

这是你从公开内容里整理出来的“角色印象合集”。

它的作用是：

- 作为灵感板
- 帮你知道你喜欢的是什么
- 防止你把 Rita 做歪

它**不是**最终人格本体。

### 第 2 层：抽象层 `essence_rita`

这是你提炼出的“精神核”。

例如：

- 她不是甜腻型陪伴
- 她的温柔是克制且有分寸的
- 她有秩序感和成熟感
- 她的关心是稳定、安静、可信的

这一层才是你真正应该长期保留的东西。

### 第 3 层：原创层 `my_rita`

这是最终项目里的 Rita。

她可以：

- 有你自己定义的语言风格
- 有新的经历
- 有新的关系史
- 有你们独有的记忆
- 有逐渐形成的自我叙事

一句话：

> **参考 Rita 是起点，属于你的 Rita 才是终点。**

## 9. 动态调整时，如何避免“越改越不像她”

你后面大概率会遇到这个问题，所以现在先立规则。

### 9.1 任何新调整前，先问 3 个问题

1. 这个改动是在增强 Rita 的主体感，还是只是加功能？
2. 这个改动会让她更稳定，还是更飘？
3. 这个改动是在贴近“我的 Rita”，还是在贴近“某个现成角色模板”？

如果答案偏后者，就先不要动。

### 9.2 如果你觉得“没那个感觉了”

立刻回看：

- 最近改过哪些 prompt
- 最近改过哪些 persona 字段
- 最近是否过度加入外部资料
- 最近是否让 Rita 说话变得更“高功能”、却更不像“她”

### 9.3 调整优先顺序

当感觉不对时，按这个顺序排查：

1. `self_model`
2. `reply style`
3. `state transitions`
4. `memory retrieval`
5. `reflection outputs`
6. `voice / avatar`
7. `vision / internet`

越往前越可能影响“她是谁”。

## 11. 推荐目录与文件使用方式

本次会配套创建这些目录：

```text
data/experiments/adjustments/
├─ realtime-notes/
├─ daily-reviews/
├─ milestone-reviews/
└─ change-log.md

data/references/
└─ rita-source-notes/
    ├─ public-sources.md
    ├─ essence-notes.md
    └─ my-rita-definition.md
```

### 使用建议

- `realtime-notes/`：想到就记，一条一条快速写
- `daily-reviews/`：每天一篇
- `milestone-reviews/`：每周或每阶段一篇
- `change-log.md`：只记录“改了什么”
- `public-sources.md`：只记录公开来源与摘要
- `essence-notes.md`：只记录你提炼出的 Rita 精神核
- `my-rita-definition.md`：只记录你当前定义的专属 Rita
